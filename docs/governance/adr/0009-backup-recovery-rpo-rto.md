## 1. 맥락(Context)

ADR-0001 G4-3은 "ADR-0009 RPO/RTO 등급 충족 + 분기 1회 복구 시뮬레이션
성공 기록"을 상용화 게이트로 명시한다. ADR-0004 §7은 데이터를 A/B/C
3등급으로 나눴다. 현재(`docs/infra/ops/backup-restore.md`):

- 백업 저장소·암호화·KMS 미지정
- RPO/RTO 미지정
- 복구 리허설 책임자·주기 미지정
- 테넌트 단위 부분 복원 절차 부재
- 백업 무결성 자동 검증 부재

이 상태로는 어떤 데이터 손상 사고에서도 SLA를 약속할 수 없다.
또한 ADR-0005 Tier 2/3 고객은 **테넌트 단위 백업 분리·복원**이
계약 요구사항이 될 수 있다.

근거 인벤토리:
- `docs/infra/ops/backup-restore.md`
- `docs/ops/runbook-db-backup-restore.md`
- ADR-0001 G4-3, ADR-0004 §7 (데이터 등급), ADR-0005 (Tier별 백업 요구)

## 2. 결정(Decision)

OneERP는 데이터 등급(A/B/C) × 테넌트 Tier(1/2/3)의 매트릭스에 따라
백업·복구 정책을 차등 적용한다. 6개 핵심 결정:

### 2.1 RPO/RTO 표준 (등급별)
ADR-0004 §7과 정합. 본 ADR이 SLA 정의 본체.

| 등급 | RPO | RTO | 백업 | 복제 | 보존 |
|------|-----|-----|------|------|------|
| A (Critical) | ≤ 5분 | ≤ 30분 | 1시간 풀 + WAL 연속 | 동기 2복제 | 7년(법정) |
| B (Operational) | ≤ 1시간 | ≤ 2시간 | 6시간 풀 + WAL | 비동기 1복제 | 1년 + 월별 7년 |
| C (Auxiliary) | ≤ 24시간 | ≤ 8시간 | 일 1회 | 없음 | 90일 |

### 2.2 백업 종류
- **풀 백업(Full)**: PostgreSQL `pg_basebackup` + FerretDB 메타
- **WAL 연속**: `pgbackrest` 또는 `wal-g` 아카이브 (등급 A/B)
- **논리 백업**: `mongodump` 호환 도구로 컬렉션별 (테넌트 부분 복원용)
- **오브젝트 스토리지**: S3 호환 cross-region 복제

### 2.3 저장소·암호화
- 1차: 동일 리전 별도 가용영역 오브젝트 스토리지
- 2차: cross-region 복제 (등급 A 의무, B 권장)
- 암호화: 전송 TLS 1.3, 정지 AES-256-GCM (KMS 관리)
- 키 회전: 분기 1회 자동
- 액세스: PIM 승인 + 4-eye (감사 로그)

### 2.4 무결성 검증
- 백업 직후 SHA-256 체크섬 + 매니페스트 서명
- 일 1회 무작위 백업 1건 자동 복원 + smoke 검증
- 실패 시 즉시 Critical 알림(ADR-0008 라우팅)

### 2.5 복구 절차 표준
복구 유형 5종. 각 유형에 대해 `docs/ops/runbook-restore-<type>.md` 발행.

| 유형 | 사용 | RTO 영향 |
|------|------|----------|
| Point-in-time (PITR) | 데이터 손상 → 시점 복원 | 등급 RTO 준수 |
| Tenant Partial | Tier 2/3 단일 테넌트 복원 | RTO + 테넌트 복원 시간 |
| Cluster Failover | 1차 클러스터 장애 | ≤ 5분 (자동) |
| Cross-Region DR | 리전 장애 | ≤ 4시간 (수동 승급) |
| Single Document | 운영 실수 단건 복원 | ≤ 30분 |

### 2.6 검증 의무
- **분기 복구 리허설** (G4-3 게이트): 등급 A 데이터에 대해 PITR + Tenant
  Partial 시뮬레이션 분기 1회. 결과 보고서 `docs/kb/restore-drill-YYYYQN.md`
- **연 1회 DR 시뮬레이션**: Cross-Region 페일오버, 8시간 게임데이
- 미실시 시 그 분기 모든 신규 모듈 라벨 승급 차단

- **범위 In**: FerretDB/DocumentDB, 오브젝트 스토리지, 시크릿 메타데이터
  (값 제외), 설정/매니페스트.
- **범위 Out**:
  - 시크릿 값 백업(별도 시크릿 매니저 자체 백업)
  - 외부 SaaS 데이터(통합 허브 ADR로 책임 분리)
  - 로그·메트릭(자체 보존, 백업 대상 아님)

## 3. 대안(Alternatives Considered)

### 대안 A — 단일 RPO/RTO (예: 1시간/4시간)
- 단점: 등급 A 손실 5분과 24시간 사이 트레이드오프 불능. 비용 비효율.
- 채택하지 않은 이유: ADR-0004 등급화와 충돌.

### 대안 B — 클라우드 매니지드 백업 단일 (RDS automated 등)
- 장점: 운영 단순.
- 단점: cross-region·테넌트 부분 복원 제한, lock-in.
- 채택하지 않은 이유: ADR-0005 Tier 2/3 요구 미충족.

### 대안 C — 백업 없이 복제만 의존
- 단점: 논리 손상(잘못된 UPDATE)이 즉시 복제 → 복구 불능.
- 채택하지 않은 이유: 사고 1순위 시나리오 무대응.

### 대안 D — 현 상태 유지 (정책 미정의)
- 채택하지 않은 이유: G4-3 미달.

## 4. 근거(Rationale)

| 평가 축 | 점수 | 비고 |
|---------|------|------|
| 비용 | 3/5 | 등급 A의 동기 복제 + WAL 연속이 비용 견인 |
| 리스크 | 5/5 | 사고 시 단계적 복구 + 분기 리허설 |
| 운영 | 4/5 | 등급 명시로 일상 결정 자동화 |
| 팀 역량 | 3/5 | DR 게임데이는 신규 역량, 점진 학습 |

## 5. 영향(Consequences)

### 5.1 긍정적
- SLA 약속 가능.
- 사고 시 RTO/RPO 객관 판단.
- 분기 리허설로 절차 부패 방지.

### 5.2 부정적
- 등급 A 비용 (스토리지·인스턴스).
- 분기 리허설 인력 시간 (게임데이 4~8시간 × 4회/년).

### 5.3 호환성/마이그레이션
- 기존 데이터는 `__meta.dataClass` 기본 B로 표시, 모듈 오너가 검토 후
  A/C 재분류.

### 5.4 측정 지표

| 지표 | 현재 | 목표(6개월) |
|------|------|-------------|
| 등급 분류 컬렉션 | 0% | 100% |
| 백업 무결성 검증 성공률 | n/a | ≥ 99% |
| 분기 복구 리허설 실시 | 0회 | 1회/분기 |
| RTO 준수율(시뮬레이션) | n/a | 100% |
| RPO 준수율(시뮬레이션) | n/a | 100% |

## 6. Tier × 등급 매트릭스

| | Tier 1 (Shared) | Tier 2 (Schema) | Tier 3 (Dedicated) |
|---|---|---|---|
| 등급 A | 공유 백업, 테넌트 단위 추출 | 테넌트별 부분 백업 | 테넌트 전용 백업 일정 |
| 등급 B | 공유 백업 | 공유 백업 + 테넌트 추출 | 테넌트 전용 |
| 등급 C | 공유 백업 | 공유 백업 | 테넌트별 (옵션) |
