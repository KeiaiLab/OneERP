## 1. 맥락(Context)

> 결정이 필요하게 된 외부 사실, 제약, 트리거를 객관적으로 기록한다.
> 의견이나 결론을 섞지 않는다.

- 어떤 문제 또는 기회가 발생했는가?
- 왜 지금 결정해야 하는가? (deadline, 의존 작업, 리스크 임계 등)
- 현재 코드/인프라/조직의 제약은 무엇인가?
- 관련 인벤토리/스펙/메트릭 근거 링크
  - 예: `docs/infra/inventory/data-storage.md`
  - 예: `docs/infra/ops/slo.md` 측정값
  - 예: 사고 이력 `docs/kb/incident/INC-NNNN-*.md` (있을 경우)

## 2. 결정(Decision)

> "무엇을 한다"를 한 문장으로 단정한다. 모호한 어휘 금지.

- **선택안**: (단정형 한 문장)
- **범위 In**: 이 결정이 적용되는 대상
- **범위 Out**: 이 결정이 적용되지 않는 대상 (혼선 방지를 위해 명시)
- **발효 시점**: 즉시 / 특정 phase 완료 후 / 조건 충족 시
- **유효 기간**: 무기한 / N개월 / 다음 마일스톤까지
