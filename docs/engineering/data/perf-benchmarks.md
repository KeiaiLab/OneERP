# 성능 벤치마크

## 대상 규모

대기업 확장 대비 성능 기준(동시 3만명, ERP 활성 사용자 5만명)으로 설계한다.

| 항목 | 값 |
|------|-----|
| 전체 직원 수 | 270,000명 |
| ERP 활성 사용자 | ~50,000명 |
| 동시 접속(일반) | 10,000명 |
| 동시 접속(피크: 월말 마감/급여) | 30,000명 |
| 일일 트랜잭션 | 1,000,000건+ |
| 연간 문서 증가 | 10억 건 |

## 성능 목표 (SLO 연계)

> SLO 수치 상세는 `docs/infra/ops/slo.md` 참조

### API 응답시간

| 유형 | p95 | p99 |
|------|-----|-----|
| 일반 API (CRUD) | < 200ms | < 500ms |
| 리스트 조회 (1,000건 페이지네이션) | < 300ms | < 800ms |
| 리포트 집계 (단일 테넌트) | < 3초 | < 5초 |
| 대시보드 위젯 | < 500ms | < 1초 |

### 처리량

| 유형 | 목표 |
|------|------|
| 동시 API 요청 처리 | 30,000 RPS (피크) |
| 배치 처리 (급여 계산, 27만명) | < 30분 |
| 월말 마감 집계 | < 1시간 |

### 데이터 접근

| 유형 | 목표 |
|------|------|
| 단건 문서 조회 | < 10ms |
| 인덱스 기반 쿼리 | < 50ms |
| 풀 스캔 (금지, 감지 시 알림) | N/A |

## SLI 정의 (slo.md 연계)

| SLI | 측정 방법 | 목표 |
|-----|----------|------|
| 가용성 | 핵심 API 성공률 (1 - 5xx/전체) | 99.9% |
| 지연 | API p95 응답시간 | < 200ms |
| 지연 (리스트) | 리스트 조회 p95 응답시간 | < 300ms |
| 에러율 | 전체 요청 대비 에러 비율 | < 0.1% |
| 비동기 작업 | 작업 큐 지연 p95 | < 30초 |
| 비동기 작업 | 작업 큐 실패율 | < 0.5% |

## 벤치마크 시나리오

### 시나리오 1: 리스트 조회 (핵심)

- **조건**: tenant_id 필터, status 필터, 최신순 정렬, 1,000건 페이지네이션
- **데이터**: 테넌트당 100만 건 이상
- **목표**: p95 < 300ms
- **도구**: k6 부하 테스트, 동시 사용자 10,000명

### 시나리오 2: 리포트 집계 (핵심)

- **조건**: 월간 매출 집계, 계정별 원장 합계, 재고 평가
- **데이터**: 월간 트랜잭션 8,000만 건
- **목표**: p95 < 3초
- **도구**: k6 부하 테스트, 동시 리포트 100건

### 시나리오 3: 피크 부하

- **조건**: 월말 마감 + 급여 산출 동시 진행
- **동시 사용자**: 30,000명
- **목표**: API p95 < 500ms (일반 대비 2.5배 허용)
- **도구**: k6 분산 부하 테스트

### 시나리오 4: 데이터 증가 내구성

- **조건**: 3년치 데이터(30억 건) 상태에서 쿼리 성능
- **목표**: 리스트 조회 p95 < 500ms (초기 대비 1.7배 이내)
- **도구**: 대용량 시드 데이터 + k6

## 벤치마크 실행 규칙

1. **CI 통합**: PR 머지 시 핵심 시나리오(1, 2) 자동 실행
2. **회귀 탐지**: 이전 결과 대비 20% 이상 저하 시 자동 실패
3. **주간 전체 실행**: 시나리오 1~4 전체를 주간 스케줄로 실행
4. **결과 저장**: 벤치마크 결과를 시계열 DB에 저장하여 추이 분석
