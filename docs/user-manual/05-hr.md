# 인사 모듈 (Human Resources Module)

## 개요 (Overview)

인사 모듈은 직원 정보 관리 (Employee Management), 조직 구조 (Organization Structure), 채용 (Recruitment), 휴가/근태 (Leave/Attendance), 교대근무 (Shift), 교육훈련 (Training), 인사평가 (Appraisal) 등 인적자원 관리 전반을 지원한다.

## 사전 조건 (Prerequisites)

- HR 서비스와 직원/부서 마스터가 준비되어 있어야 한다.
- 휴가, 근태, 채용 흐름을 볼 권한이 필요하다.
- 급여 모듈과 연계할 기본 인사 데이터가 있어야 한다.

## 완료 조건 (Completion Criteria)

- 직원, 조직 구조, 휴가, 근태, 채용 흐름을 설명할 수 있다.
- 인사 데이터가 급여 처리에 연결되는 지점을 확인할 수 있다.
- 다음 급여 모듈 문서로 이동할 수 있다.

## 주요 기능 (Key Features)

- 직원 관리 (Employee Management)
- 부서/직위 관리 (Department/Designation Management)
- 채용 (Recruitment): 공고 (Job Opening) → 지원 (Application) → 면접 (Interview) → 합격 (Offer) → 온보딩 (Onboarding)
- 휴가 관리 (Leave Management)
- 근태 관리 (Attendance Management)
- 교대근무 (Shift Management)
- 인사평가 (Appraisal)
- 교육훈련 (Training)

```
채용공고         지원접수         면접           채용제안         입사절차
(Job Opening) → (Application) → (Interview) → (Job Offer) → (Onboarding)
                                                                ↓
                                                          직원 등록
                                                       (Employee Reg.)
```

## 상세 기능 (Detailed Features)

### 직원 관리 (Employee Management)

#### 생성 (Create)
1. **인사 (HR) > 직원 (Employee)** 메뉴에서 **"신규 (New)"** 를 클릭한다.
2. 사번 (Employee ID), 성명 (Name), 부서 (Department), 직위 (Designation)를 입력한다.
3. 입사일 (Date of Joining), 생년월일 (Date of Birth), 고용 유형 (Employment Type), 보고 상사 (Reports To)를 입력한다.
4. 연락처 (Contact), 이메일 (Email), 회사 (Company)를 입력해 급여/조직도 연동 기준 데이터를 완성한다.
5. **"저장 (Save)"** 을 클릭한다.

#### 직원 디렉터리 (Employee Directory)
1. `GET /api/v1/employees/directory?status=active` 로 재직 직원 카드를 조회한다.
2. 각 카드에서 관리자 이름 (`manager_name`)과 직속 인원 수 (`direct_report_count`)를 확인해 보고라인을 점검한다.
3. 존재하지 않는 직원이나 본인을 보고 상사로 지정하면 저장되지 않는다.
4. 팀원이 연결된 관리자 직원은 삭제할 수 없으므로, 팀원 보고라인을 비운 뒤 삭제한다.

#### 인사이동 (Employee Transfer)
1. **인사 (HR) > 인사이동 (Employee Transfer)** 에서 **"신규 (New)"** 를 클릭한다.
2. 대상 직원 (Employee)을 선택한다.
3. 변경 내용 (Changes: 부서 Department, 직위 Designation)을 입력한다. 대상 부서/직급이 존재하지 않으면 저장되지 않는다.
4. 발령일 (Effective Date)을 지정하고 초안을 저장한다.
5. 목록 워크벤치에서 `summary.draft_count/submitted_count/effective_today_count/payroll_sync_pending_count` 와 행별 `status_badge`, `recommended_action`, `available_actions` 를 확인한다.
6. 발령을 실행할 준비가 되면 **"제출 (Submit)"** 한다. 제출 즉시 직원 마스터의 부서/직급이 갱신되고 급여 동기화용 `EMPLOYEE_UPDATED` 이벤트가 기록된다.
7. 상세 또는 `/summary` 에서 `change_summary`, `impact_summary`, `sync_summary` 를 확인해 변경 범위, 현재 직원 상태, 급여 동기화 대기 여부를 함께 검토한다.
8. 발령을 되돌려야 하면 **"취소 (Cancel)"** 로 직원 마스터를 원래 부서/직급으로 복원한다.

### 부서 및 직위 (Department & Designation)

#### 부서 관리 (Department Management)
1. **인사 (HR) > 부서 (Department)** 에서 조직도 (Organization Chart)를 관리한다.
2. 상위 부서 (Parent Department)를 선택하고 하위 부서 (Sub-Department)를 추가한다.
3. 존재하지 않는 상위 부서를 지정하거나 본사 아래 팀을 다시 본사 상위에 두는 순환 구조는 저장되지 않는다.
4. 조직도 API (`GET /api/v1/departments/tree`)로 루트 부서부터 하위 부서, 부서별 인원 수를 함께 확인할 수 있다.
5. 하위 부서가 남아 있거나 직원이 배정된 부서는 삭제할 수 없으므로, 하위 부서를 먼저 정리하고 직원 부서를 이동한 뒤 삭제한다.

#### 직급 관리 (Designation Management)
1. **인사 (HR) > 직급 (Designation)** 에서 직급 체계를 관리한다.
2. 직급별 정렬 순서(`rank_order`)를 입력해 사원 → 대리 → 과장처럼 화면 표시 순서를 고정한다.
3. **직급 체계 조회** API (`GET /api/v1/designations/hierarchy`)로 직급 순서와 직급별 현재 재직 인원 수를 확인할 수 있다. 퇴사 처리된 직원은 집계에서 제외된다.
4. 재직 중인 직원이 사용하는 직급은 삭제할 수 없으므로, 직원 직급을 먼저 변경하거나 퇴사 처리한 뒤 삭제한다.

### 채용 (Recruitment)

#### 채용 프로세스 (Recruitment Process)
1. **인사 (HR) > 채용공고 (Job Opening)** 에서 채용 포지션을 등록한다. (Register a job opening.)
2. 지원자가 접수되면 **인사 (HR) > 입사지원자 (Job Applicant)** 에 등록한다.
3. **면접라운드 (Interview Round)** 를 생성하고 면접을 진행한다. (Create interview rounds and conduct interviews.)
4. **면접피드백 (Interview Feedback)** 을 기록한다.
5. 채용 결정 시 **채용제안서 (Job Offer)** 를 발송한다. (Send a job offer upon hiring decision.)
6. 수락 후 **입사절차 (Onboarding)** 를 시작한다.

#### 입사 절차 (Onboarding)
1. **인사 (HR) > 입사절차 (Onboarding)** 에서 온보딩 체크리스트를 관리한다. (Manage the onboarding checklist.)
2. IT 장비 지급 (IT Equipment), 계정 생성 (Account Setup), 오리엔테이션 (Orientation) 등을 추적한다.

### 휴가 관리 (Leave Management)

#### 휴가 유형 설정 (Leave Type Setup)
1. **인사 (HR) > 휴가유형 (Leave Type)** 에서 연차 (Annual Leave), 병가 (Sick Leave), 경조사 (Compassionate Leave) 등을 정의한다.
2. 유급 (Paid)/무급 (Unpaid) 여부, 최대 일수 (Max Days)를 설정한다.
3. 목록 워크벤치에서 `status_badge` 와 `summary.policy_count/balance_employee_count/open_application_count` 를 함께 확인해 정책 미할당/대기 신청 적체를 한 번에 점검한다.
4. 정책·잔액·휴가신청 이력이 남아 있는 유형은 삭제할 수 없으므로, 관련 정책과 사용 이력을 먼저 정리한 뒤 유형을 폐기한다.

#### 휴가 신청 (Leave Application)
1. **인사 (HR) > 휴가신청 (Leave Application)** 에서 **"신규 (New)"** 를 클릭한다.
2. 휴가 유형 (Leave Type), 기간 (Period)을 선택한다. 비활성 휴가유형, 퇴사 직원, 시작일이 종료일보다 늦은 요청은 저장되지 않는다.
3. 사유 (Reason)를 입력하고 **"제출 (Submit)"** 한다.
4. 목록 워크벤치에서 `status_badge`, `leave_balance_summary.remaining_days`, `leave_balance_summary.remaining_after_request`, `summary.open_count/approved_count/insufficient_balance_count` 를 함께 확인해 승인 대기와 잔액 부족 후보를 한 번에 점검한다.
5. 상세 또는 `/summary` 응답의 `recommended_action` 과 `available_actions` 를 기준으로 승인권자가 **"승인 (Approve)"**, **"반려 (Reject)"**, 또는 잔액 조정 검토를 수행한다.
6. 승인 직후 `leave_balances.total_used` 와 `balance` 가 즉시 갱신되므로 급여 마감 전 별도 배치 없이 잔액 변화를 바로 확인할 수 있다.

#### 휴가 잔액 확인 (Leave Balance)
1. **인사 (HR) > 휴가잔액 (Leave Balance)** 에서 직원별 잔여 휴가를 확인한다. (Check remaining leave balance per employee.)
2. `GET /api/v1/leave-balances?employee_id=...&fiscal_year=...` 워크벤치는 `summary.employee_count/expiring_soon_count/carry_forward_ready_count`, 행별 `status_badge`, `recommended_action`, `summary.expected_carry_forward_days` 를 함께 반환해 만료 위험과 연말 이월 후보를 한 화면에서 점검한다.
3. 상세 점검은 `GET /api/v1/leave-balances/{id}/summary` 로 수행한다. `carry_forward_summary.carry_forward_cap_days`, `expected_carry_forward_days`, `expires_in_days`, `utilization_rate_pct` 를 보고 이월 실행 또는 사용 촉진 여부를 결정한다.
4. `available_actions` 에 `open_leave_applications`, `run_carry_forward`, `view_leave_report` 가 포함되면 신청 이력 확인, 이월 실행, 연도별 리포트 확인으로 바로 이동할 수 있다.
5. 연초 자동 부여는 `POST /api/v1/leave-balances/grant-annual`, 연말 이월은 `POST /api/v1/leave-balances/carry-forward`로 실행한다. 둘 다 회계연도와 직원 목록을 받아 처리 결과를 즉시 반환한다.
6. 휴가 신청 승인 직후 `total_used` 와 `balance` 가 다시 계산되므로 급여 마감 전 별도 배치 없이 잔액 변화를 바로 확인할 수 있다.
7. `GET /api/v1/leave-balances/report?employee_id=...&fiscal_year=...` 로 해당 연도의 총 부여/사용/잔여를 요약 조회한다.

### 근태 관리 (Attendance Management)

#### 출퇴근 기록 (Attendance Record)
1. **인사 (HR) > 출퇴근 (Attendance)** 에서 근태 현황을 확인한다.
2. `POST /api/v1/attendances/check-in` 으로 출근을 기록한다. `capture_channel=mobile_widget` 또는 `kiosk`이면 IP 또는 GPS 좌표를 함께 보내야 하며, 응답의 `location_summary.location_status=verified`로 저장 여부를 확인한다.
3. 체크인 응답에는 `status_badge`, `location_summary`, `available_actions`가 함께 포함되어 모바일/키오스크 출근 채널을 같은 화면에서 비교할 수 있다.
4. `POST /api/v1/attendances/{id}/check-out` 으로 퇴근을 기록하면 `working_hours`, `early_leave_minutes`, `status_badge`가 즉시 갱신된다.
5. `GET /api/v1/attendances?capture_channel=mobile_widget&location_status=verified` 로 모바일 근태 워크벤치를 조회하면 `summary.mobile_widget_count`, `summary.location_verified_count`, `summary.checked_in_count`를 동시에 확인할 수 있다.

#### 초과근무 (Overtime)
1. **인사 (HR) > 초과근무기록 (Overtime Record)** 에서 초과근무를 등록한다.
2. 초과근무정책 (Overtime Policy)에 따라 수당 (Allowance)이 계산된다.

### 교대근무 (Shift Management)

1. **인사 (HR) > 교대유형 (Shift Type)** 에서 주간 (Day)/야간 (Night)/교대 (Rotation) 근무 유형을 정의한다.
2. **인사 (HR) > 교대배정 (Shift Assignment)** 에서 직원별 교대 스케줄을 설정한다.
3. **인사 (HR) > 교대변경요청 (Shift Change Request)** 에서 변경을 요청할 수 있다.

### 인사평가 (Appraisal)

1. **인사 (HR) > 평가주기 (Appraisal Cycle)** 에서 평가 기간 (Period)을 설정한다.
2. **인사 (HR) > 목표설정 (Goal Setting)** 에서 직원별 목표를 등록한다. (Register goals per employee.)
3. **인사 (HR) > 인사평가 (Appraisal)** 에서 평가를 진행한다.
4. 평가 결과를 기반으로 급여 조정 (Salary Adjustment), 승진 (Promotion)을 결정한다.

### 교육훈련 (Training)

1. **인사 (HR) > 학습과정 (Training Course)** 에서 교육 과정을 등록한다.
2. **인사 (HR) > 학습등록 (Training Enrollment)** 에서 직원을 과정에 등록한다.
3. 이수 후 **인사 (HR) > 학습인증 (Training Certificate)** 에서 인증서를 발급한다.

## FAQ

- **Q: 휴가 잔액 (Leave Balance)은 자동으로 계산되나요?**
  A: 네, 휴가 유형별 부여 일수와 사용 일수를 기반으로 자동 계산됩니다. (Yes, it is auto-calculated based on allocated and used days per leave type.)

- **Q: 인사이동 (Employee Transfer) 시 급여도 변경되나요?**
  A: 기본 급여 구조는 별도로 조정해야 하지만, 인사이동 제출/취소 시 `EMPLOYEE_UPDATED` 이벤트가 자동 기록되어 급여 동기화 검토 지점을 제공합니다. (Salary structures still need separate updates, but submitting/cancelling a transfer records an `EMPLOYEE_UPDATED` event so payroll sync can react.)
